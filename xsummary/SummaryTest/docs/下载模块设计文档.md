# 下载模块设计文档

## 1. 模块概述

本模块是一个基于 Android + Kotlin + Hilt + Room + Retrofit 的应用下载展示模块，负责完成以下能力：

- 拉取应用榜单/推荐列表
- 展示应用基础信息与下载状态
- 对接应用中心 SDK 执行下载、暂停、继续、打开等操作
- 持久化下载进度，并在冷启动后恢复下载状态

当前模块以 `AppFragment` 为 UI 入口，以 `DownloadAppUserCase` 为业务编排中心，以 `AppRepository` 和 `DownloadRepository` 为数据访问核心。

## 2. 设计目标

- 统一管理“应用列表数据”和“下载状态数据”
- 通过响应式状态流驱动 UI，减少手动刷新成本
- 隔离第三方下载 SDK，便于替换和测试
- 支持进度持久化与冷启动恢复
- 保持展示层、业务层、数据层职责清晰

## 3. 总体架构

模块采用典型分层架构：

- UI 层：页面展示、事件分发、列表渲染
- Domain 层：业务编排、状态聚合、交互决策
- Data 层：远程接口、下载 SDK、数据库持久化
- DI 层：依赖注入与对象生命周期管理

```text

```

### 5.2 Domain 层

#### 5.2.1 `DownloadAppUserCase`

入口文件：[DownloadAppUserCase.kt](/Users/xiongxingheng/Desktop/Develop/Samples/SampleSummary/xsummary/SummaryTest/src/main/java/com/xxh/summary/download/domain/DownloadAppUserCase.kt)

职责：

- 聚合应用列表与下载状态
- 负责 UI 展示模型转换
- 负责点击行为路由
- 负责对外暴露下载监听能力

核心方法：

- `getShowAppsFlow(scope)`
  - 组合 `appRepository.loadTopApps()` 与 `downloadRepository.stateFlow`
  - 将 `AppInfo + DownloadState` 合并为 `AppUIModel`
  - 输出 `StateFlow<AppUiState>`
- `handleAction(type, app)`
  - 根据点击位置与安装状态决定后续行为
- `clickDownload(...)`
  - 根据当前 `Status` 执行 start/pause/resume/open/deeplink
- `registerDetailDownloadListener(packageName)`
  - 详情跳转前补充注册下载监听

设计特点：

- 通过 `combine` 实现“静态应用信息”和“动态下载状态”的融合
- 展示模型只在 Domain 层生成，避免 UI 层直接感知 Repository 细节

#### 5.3.2 下载子层

核心文件：

- [AppCenterSdk.kt](/Users/xiongxingheng/Desktop/Develop/Samples/SampleSummary/xsummary/SummaryTest/src/main/java/com/xxh/summary/download/data/sdk/AppCenterSdk.kt)
- [RealAppCenterSdk.kt](/Users/xiongxingheng/Desktop/Develop/Samples/SampleSummary/xsummary/SummaryTest/src/main/java/com/xxh/summary/download/data/sdk/RealAppCenterSdk.kt)
- [DownloadRepository.kt](/Users/xiongxingheng/Desktop/Develop/Samples/SampleSummary/xsummary/SummaryTest/src/main/java/com/xxh/summary/download/data/repository/DownloadRepository.kt)

设计思路：

- `AppCenterSdk` 作为下载能力抽象层，屏蔽具体 SDK 实现
- `RealAppCenterSdk` 负责与应用中心库交互
- `DownloadRepository` 负责状态收敛、持久化和恢复

`RealAppCenterSdk` 主要职责：

- 初始化 `NeoDownloadManager`
- 判断是否支持下载能力
- 处理 CTA 状态检查
- 发起下载、暂停、继续、查询状态、注册回调
- 将 SDK 状态码转换为模块内 `Status`

`DownloadRepository` 主要职责：

- 持有内存态 `MutableStateFlow<Map<String, DownloadState>>`
- 处理下载开始、暂停、继续、打开
- 将 SDK 回调统一更新到内存状态
- 将状态异步落库到 Room
- 冷启动后从数据库恢复，并向 SDK 再同步一次真实状态

关键设计点：

- 内存态采用 `Map<packageName, DownloadState>`，方便按包名快速定位
- DB 写入对 `DOWNLOADING` 状态做了 1 秒节流，降低高频落库开销
- 恢复阶段先读 DB，再查 SDK，最后重新注册回调，保证冷启动后继续接收状态更新

## 7. 核心流程设计

### 7.1 页面加载流程

```text
AppFragment 初始化
    -> AppViewModel 暴露 state
    -> DownloadAppUserCase.getShowAppsFlow()
    -> AppRepository.loadTopApps() 发起接口请求
    -> DownloadRepository.stateFlow 提供下载状态
    -> combine 合并为 AppUiState.Success
    -> AppAdapter 渲染列表
```

### 7.2 下载操作流程

```text
用户点击“下载/暂停/继续/安装/打开”
    -> AppAdapter 回调 ClickType.DOWNLOAD
    -> AppViewModel.handleAction()
    -> DownloadAppUserCase.clickDownload()
    -> DownloadRepository.start/pause/resume/open()
    -> AppCenterSdk 执行真实下载动作
    -> SDK 回调 progress/status
    -> DownloadRepository.update()
    -> stateFlow 更新
    -> UI 自动刷新
```

### 7.3 条目点击流程

```text
用户点击列表项
    -> ClickType.ITEM
    -> DownloadAppUserCase.handleAction()
    -> 若已安装则 open(packageName)
    -> 否则 jumpDeepLink(detailUrl)
    -> 注册详情页下载监听
```

### 7.4 冷启动恢复流程

```text
DownloadRepository.init()
    -> sdk.initSdk()
    -> restore()
    -> DAO.getAll() 读取历史任务
    -> queryDownloadStatusSync() 从 SDK 查询真实状态
    -> registerCallback() 恢复监听
    -> _stateFlow.emit(map)
    -> UI 恢复展示
```

## 8. 状态机设计

下载按钮的状态流转如下：

```text
IDLE -> DOWNLOADING -> PAUSED -> DOWNLOADING
DOWNLOADING -> SUCCESS
DOWNLOADING -> FAILED
SUCCESS -> INSTALLING -> INSTALLED
INSTALLED -> OPEN
FAILED -> DOWNLOADING
```

当前按钮文案映射：

- `IDLE` -> 下载
- `DOWNLOADING` -> 暂停
- `PAUSED` -> 继续
- `SUCCESS` -> 安装
- `INSTALLING` -> 安装中
- `INSTALLED` -> 打开
- `FAILED` -> 重试

## 9. 线程与并发设计

- `DownloadRepository` 使用 `CoroutineScope(SupervisorJob + Dispatchers.IO)` 处理下载状态更新与数据库落库
- UI 状态通过 `StateFlow` 暴露，天然支持多订阅者
- `restore()` 中使用 `suspendCancellableCoroutine` 将 SDK 异步查询转成挂起函数，保证状态同步完成后再统一下发
- `setDownloadListener()` 通过记录 `callbackJob` 避免重复订阅造成泄漏

## 12. 当前限制与待完善项

基于当前代码，模块还存在以下待完善点：

- `DownloadAppUserCase.isInstalled()` 当前固定返回 `false`，尚未接入真实安装状态判断
- `DownloadAppUserCase.jumpDeepLink()` 尚未实现，点击条目后的详情跳转仍为空实现
- `RealAppCenterSdk.open()` 尚未实现，已安装后的“打开”能力未真正落地
- `AppFragment` 中 `Loading/Error` 仅保留注释，没有独立视图反馈
- `item_app.xml` 中存在 `tv_status`，但 `AppAdapter` 当前未写入状态文案
- `AppRepository` 仅对 `loadTopApps()` 做了缓存，缓存策略较简单，不区分失效时间
- 成功安装后的历史记录清理逻辑被注释，数据库中可能长期保留已完成任务
- 缺少单元测试、UI 测试和下载状态恢复测试
